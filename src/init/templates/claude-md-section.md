## WP Playground dev environment

Generated by `krokedil-playground init --update` — edits between the markers will be overwritten. Config: `playground.config.mjs`; full docs: `node_modules/@krokedil/wp-playground-tools/README.md`.

- `__PM__ run playground:start` — persistent dev site on :__START_PORT__ (worktree-isolated; `--fresh` reprovisions)
- `__PM__ run playground:server-development` / `-demo` — ephemeral servers on :__DEV_PORT__ / :__DEMO_PORT__
- __FLAGS_NOTE__
- `--tunnel` — public https URL via ngrok (for webhooks/callbacks); `--https` — local mkcert https on the mode port +400
- `--tunnel-domain=<host|none>` — per-run tunnel domain override (implies `--tunnel`); use for a second simultaneous worktree: another reserved domain, or `none` for an ephemeral URL
- **Active proxy URL** (`--tunnel`/`--https`): read `.playground/proxy-url.txt` — the file exists only while a proxy runs. ngrok request inspector/replay: http://127.0.0.1:4040
- Login: `admin` / `password` — development mode auto-submits the wp-login form as admin for **local** requests only (curl checks won't consume it; `wp-login.php?action=login` forces the form locally)
- Over a `--tunnel` URL the site is public: the tunnel guard refuses `password` and requires the run's tunnel password (printed with the public URL, or `KROKEDIL_PG_TUNNEL_PASS`). Storefront, REST and webhooks stay open
- **Logged-out testing**: `?krokedil-guest=1` on any local URL logs out and stops auto-login for 12 hours in that browser/cookie jar (front-end login links would otherwise sign you back in); `?krokedil-guest=0` restores it. Per browser, development mode only, and it clears the cart
- Logs/DB of the persistent site: `~/.wordpress-playground/sites/<sha256(cwd)>/wp-content/` — `debug.log`, `uploads/wc-logs/`, SQLite at `database/.ht.sqlite`
- `.playground/` is generated (blueprints + staged assets, gitignored); write blueprints for inspection with `__PM_EXEC__ krokedil-playground compose`
